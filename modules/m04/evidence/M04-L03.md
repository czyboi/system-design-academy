# Source evidence for M04-L03

Checked 2026-11-13. Confidence is verified for the scoped claims below. Worked scenarios and design calculations are original and use illustrative assumptions.

| Claim | Supported mechanism | Primary evidence | Limits |
| --- | --- | --- | --- |
| Ownership | Functional partitioning gives a domain its own data and write authority. Cross-domain views and multi-owner changes require explicit composition and consistency design. | [Microsoft Azure Architecture Center, Data considerations, data ownership and consistency](https://learn.microsoft.com/en-us/azure/architecture/microservices/design/data-considerations) | Domain decomposition guidance. Federation here means a functional database split. |
| Sharding | Range and hash distribution offer different locality and skew properties. Shard-key lookups can target an owner and unconstrained queries can fan out. | [Microsoft Azure Architecture Center, Sharding pattern, sharding strategies](https://learn.microsoft.com/en-us/azure/architecture/patterns/sharding#sharding-strategies), [Vitess 24, Sharding](https://vitess.io/docs/24.0/reference/features/sharding/) | Online migration still requires a source-of-truth switch and routing policy. The exercise's epoch and drain are an illustrative design. |
| Ring | A key maps clockwise to a token. Multiple virtual tokens per physical node distribute intervals and let an added node take portions from several owners. | [DeCandia et al., Dynamo, SOSP 2007 §4.2 and figure 2](https://www.allthingsdistributed.com/files/amazon-dynamo-sosp2007.pdf#page=5) | Only primary ownership is counted in the illustrated movement. Replication and a hot key can add cost. |
| Directory transition | etcd v3.6 supports transactions guarded by comparisons and linearizable reads. A timed-out update may have committed. | [etcd v3.6 transactions](https://etcd.io/docs/v3.6/learning/api/#transaction), [API guarantees and client uncertainty](https://etcd.io/docs/v3.6/learning/api_guarantees/) | The epoch, fencing and mutually exclusive activation or abort transitions are a design example. The directory does not fence a database writer on its own. |
