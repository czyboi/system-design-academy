# Source evidence for M04-L01

Checked 2026-11-13. Each row verifies the scoped claim. Scenario inputs, schema sketches and traces are original examples. No third-party assets are used.

| Claim | Supported statement | Primary evidence and scope | Limits |
| --- | --- | --- | --- |
| REL-1 | PostgreSQL primary keys identify rows. A non-null foreign key requires a matching referenced key, and `ON DELETE RESTRICT` prevents deletion of a referenced row. | [PostgreSQL Global Development Group, PostgreSQL 18 §5.5.4](https://www.postgresql.org/docs/18/ddl-constraints.html#DDL-CONSTRAINTS-PRIMARY-KEYS), [§5.5.5](https://www.postgresql.org/docs/18/ddl-constraints.html#DDL-CONSTRAINTS-FK) | The referencing side may allow nulls unless declared otherwise. An ordinary foreign key neither requires any child row nor imposes uniqueness on the child. |
| REL-2 | PostgreSQL transactions group mutations into a commit or rollback. Isolation limits visibility and interference under concurrent execution. | [PostgreSQL 18 §3.4](https://www.postgresql.org/docs/18/tutorial-transactions.html), [§13.2](https://www.postgresql.org/docs/18/transaction-iso.html) | Transaction boundaries cover database operations. Durability depends on the acknowledgement and failure configuration. Read Committed does not automatically protect arbitrary read-then-write business rules. |
| REL-3 | PostgreSQL Read Committed re-evaluates a concurrent update's predicate on the updated version of a targeted row after the other writer commits. | [PostgreSQL 18 §13.2.1](https://www.postgresql.org/docs/18/transaction-iso.html#XACT-READ-COMMITTED) | Supports the single stock-row and invoice-row races. Cross-row predicates need their own concurrency design. |
| REL-4 | A join pairs rows using a matching condition. B-tree access can efficiently constrain a leading equality prefix and provide rows in index order for a matching limited query. | [PostgreSQL 18 §2.6](https://www.postgresql.org/docs/18/tutorial-join.html), [§11.3](https://www.postgresql.org/docs/18/indexes-multicolumn.html), [§11.4](https://www.postgresql.org/docs/18/indexes-ordering.html) | An index is a candidate access path. Actual plan choice depends on the workload and planner. |
| REL-5 | Amazon S3 documents strong read-after-write for object operations and atomic updates per key. | [AWS, Amazon S3 data consistency model](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html#ConsistencyModel) | Scope is S3 object operations. The upload and the database commit in the example are separate operations and have independent failure modes. |
