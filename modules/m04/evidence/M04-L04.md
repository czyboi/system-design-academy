# Source evidence for M04-L04

Checked 2026-11-13. Confidence is verified for the scoped claims below. Worked scenarios and design calculations are original and use illustrative assumptions.

| Claim | Supported mechanism | Primary evidence | Limits |
| --- | --- | --- | --- |
| Persisted view | PostgreSQL stores materialized view rows for direct reads, and a refresh replaces view contents. Results may lag the source. | [PostgreSQL 18 §39.3](https://www.postgresql.org/docs/18/rules-materializedviews.html), [REFRESH MATERIALIZED VIEW](https://www.postgresql.org/docs/18/sql-refreshmaterializedview.html) | Concurrent refresh requires a qualifying unique index and only one refresh may run at a time per view. |
| Outbox | A source transaction can write its state and an outbox record together. An outbox event includes an identifier for deduplication and an aggregate key for ordering within a Kafka partition. | [AWS Prescriptive Guidance, relational outbox pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html#using-an-outbox-table-with-a-relational-database), [Debezium, outbox table](https://debezium.io/documentation/reference/stable/transformations/outbox-event-router.html#basic-outbox-table) | A complete versioned snapshot, checkpoint and projection guard are design choices. |
| Source serialization | PostgreSQL row locks serialize writers using a shared lock row, and later Read Committed statements see prior commits plus their own earlier writes. | [PostgreSQL 18 row locks](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS), [Read Committed](https://www.postgresql.org/docs/18/transaction-iso.html#XACT-READ-COMMITTED) | The lock protocol applies to every mutation contributing to the summary. |
| Rebuild and resume | Debezium documents a consistent initial snapshot paired with log continuation. Kafka distinguishes current position and committed offset within a partition. | [Debezium PostgreSQL snapshots](https://debezium.io/documentation/reference/stable/connectors/postgresql.html#postgresql-snapshots), [Kafka 4.1 consumer positions](https://kafka.apache.org/41/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html) | Cutover coverage and a gap-free durable checkpoint are application conditions. Source and broker positions are distinct unless explicitly mapped. |
