# M10-L05 assessment — Distributed social-graph traversal

## Knowledge checks

**Q1 (LO1).** In the original edge set `(a,b),(a,c),(b,d),(c,e),(d,f),(e,f),(f,g)`, what is the minimum number of edges from a to g and one valid path?

**Answer.** Four edges; one route is `a→b→d→f→g`, and `a→c→e→f→g` is another. Layer BFS reaches `f` at depth 3 and `g` at depth 4. Stable tie breaks can choose either length-four result.

**Q2 (LO1).** Why is it wrong to share `visited` across two independent shortest-path requests from different users?

**Answer.** Visited is per-search state keyed by that query's source, graph revision and visibility policy. A global mark can cause request B to skip a node reached by A, report unreachable or reconstruct parents from another user's path. It also risks cross-user information disclosure.

**Q3 (LO1).** The frontier contains `b` on P1 and `c` on P2. What should the traversal coordinator batch, and what can it claim if P2 times out?

**Answer.** Group IDs by owning partition and issue bounded concurrent adjacency batches, with snapshot/version responses. If P2 is unavailable, the layer is incomplete, so it cannot generally prove the returned route is shortest or that no path exists; it must return a scoped incomplete result or retry within budget.

**Q4 (LO2).** Does skipping every high-degree node preserve an exact shortest-path result? Under what alternate contract is it useful?

**Answer.** No. The pruned node could lie on the only shortest route. It can be appropriate for a bounded approximate path recommendation if the product states the limitation and measures recall separately from exact correctness.

**Q5 (LO2).** A cached path `a→b→d→f→g` is reused for a viewer who cannot access edge `d-f`. Can caching by endpoints alone prove a valid result?

**Answer.** No. Include the viewer's authorized scope and graph snapshot or re-check all edges with a current authorization boundary. Endpoints do not determine access permissions. A late cache fill must not override revocation.

**Q6 (LO2).** Is GraphQL a replacement for BFS, and why can a directed graph complicate bidirectional BFS?

**Answer.** GraphQL is a typed API query language, not a traversal algorithm or graph database. Directed source→target bidirectional search needs reverse adjacency for the backward half; following outgoing edges backward computes a different relation. Use a graph traversal engine such as Gremlin/Cypher where appropriate, under its documented semantics.

## EX-1 — Authorized path across three partitions

**Inputs.** P1 owns `{a,b}`; P2 owns `{c,d}`; P3 owns `{e,f,g}`. Undirected edges: `a-b,a-c,b-d,c-e,d-f,e-f,f-g`. A viewer can read every edge initially. The coordinator runs a four-hop shortest-path search from a to g, with per-partition adjacency batch limit 50 and deadline 800 ms. During a second run P2 is delayed; a later edge-privacy change hides `d-f` for that viewer. An unrelated concurrent search uses a different source and permission scope.

**Deliverable.** Draw BFS layers, predecessor map and two shortest paths. Show exact partition request batches and why a timeout blocks a shortest proof. Compare bidirectional expansion and its termination bound. State the cache/snapshot and visibility model, what to return when a hop/edge-count cap is exhausted, and one failure test for every claimed invariant. Explain why an API using GraphQL would still require graph traversal semantics.

### Reference solution

- BFS layers `a` → `{b,c}` → `{d,e}` → `{f}` → `{g}`; two valid minimum-hop paths have length 4. With deterministic sorted neighbor order, `parent[b]=a, parent[d]=b, parent[f]=d, parent[g]=f`, returning `a-b-d-f-g`. The `c-e-f-g` path also has length 4.
- Batch layer-1 adjacency from P1 {b} and P2 {c}; layer-2 from P2 {d} and P3 {e}. At each layer use per-search visited and predecessor state. Return `incomplete` rather than a false no-path if P2 times out and exact proof requires c's neighbors.
- Bidirectional from a and g has forward depth-2 set {d,e}, backward from g has `f` at depth 1 then `d,e` at depth 2; meeting gives length 4 when the algorithm's layer completion and lower-bound condition hold. Don't stop just because an early partial RPC reports an intersection.
- For the viewer whose permissions changed, the cached `a-b-d-f-g` path may be forbidden. Recheck with the chosen authorization boundary and stable revision; `a-c-e-f-g` may remain usable if its edges are still visible. Don't reuse another viewer's visited set or endpoint-only path cache.
- A graph record can be queried behind a GraphQL API, but the backend still implements BFS/traversal or uses a graph engine. Four-hop budget means no *within-four-hop* path if all eligible layers complete; it does not prove graph-wide disconnection.
- Test high-degree clipping, one partition unavailable, concurrent viewer scopes, a late cache fill after edge removal, and graph snapshot invalidation.
