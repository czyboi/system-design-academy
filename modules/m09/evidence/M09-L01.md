# Source evidence for M09-L01

Checked 2026-11-15. The tenant roles, payout-record examples and enforcement contracts are original. The financial example assumes generic sensitive business records and makes no compliance determination.

| Claim | Primary evidence and scope | Verification and limits |
| --- | --- | --- |
| C1. Verify identity/token and independently authorize the requested object/action at the resource server. Deny by default and check each request. A network location or an authenticated workload is one input to policy. | OWASP [Authorization Cheat Sheet, Enforce Least Privileges and Validate the Permissions on Every Request](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html#validate-the-permissions-on-every-request) and NIST [SP 800-207, Zero Trust Architecture](https://csrc.nist.gov/pubs/sp/800/207/final). | Verified security guidance. Scoped membership lookup and database query predicate are scenario implementation choices. Treat claimed tenant IDs as untrusted until resolved against policy. |
| C2. TLS 1.3 authenticates the configured peers and protects bytes in transit between its endpoints. A terminating reverse proxy creates a new hop. Strip attacker-controlled identity headers at the trusted boundary and protect the upstream hop. | IETF [RFC 8446 §1](https://www.rfc-editor.org/rfc/rfc8446.html#section-1) and [RFC 9700 §4.13](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.13). | Verified TLS and OAuth reverse-proxy guidance. Browser/server TLS and workload mutual TLS use different identities. Neither policy nor authorization is delegated merely by terminating TLS. |
| C3. OAuth resource servers validate token restrictions. Audience and permitted scope constrain token use, and object-level authorization is still needed. For JWT access tokens under RFC 9068 verify profile claims and trusted signing context. | IETF [RFC 9700 §§2.2 and 2.3](https://www.rfc-editor.org/rfc/rfc9700.html#section-2.3), and OWASP [REST Security, JWT and access control](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html#jwt). | Verified for named OAuth/JWT profile guidance. Use trusted issuer/key configuration, allowed algorithms, issuer, audience, expiration and required claims. Avoid universalizing JWT semantics to opaque tokens. |
| C4. Parameter binding keeps values out of SQL syntax. Input validation enforces business shape. Context-sensitive output encoding protects a browser rendering context. Cookie-authenticated state changes need CSRF protection appropriate to credential transport. | OWASP [SQL Injection Prevention, Prepared Statements](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html#defense-option-1-prepared-statements-with-parameterized-queries), [XSS Prevention, Output Encoding](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html#output-encoding), [CSRF Prevention, Synchronizer Token Pattern](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html#synchronizer-token-pattern). | Verified for stated contexts. Parameters do not authorize access or safely substitute arbitrary SQL identifiers. CSRF and XSS have distinct attacker controls and mitigations. |
| C5. Scope encryption at rest to the theft or exposure threat and separate key access from stored ciphertext. Limit access to secrets, automate rotation and limit sensitive telemetry. | OWASP [Cryptographic Storage, Architectural Design and Separation of Keys and Data](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html#separation-of-keys-and-data), [Secrets Management §§2.3–2.4](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html#23-access-control), [Logging, Data to Exclude](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html#data-to-exclude). | Verified recommendations. Disk/backups encryption and separately authorized field encryption address different compromise paths. No guarantee against a compromised authorized plaintext endpoint. |
