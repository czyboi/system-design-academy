# Companion assessment for M09-L01

## Practical exercise

**EX-1.** A merchant portal serves financial statements through a reverse proxy, statement API and database. Assume users belong to one or more tenants through a trusted membership service. Under the configured user-delegated JWT access-token profile, the validated issuer and subject identify user Bo. The token is valid for the statement API and permits the general `statements:read` scope. Bo belongs to tenant C. Statement `s-9` belongs to tenant D. The API uses a database account that can read statements for all tenants, and the database and backups are encrypted at rest. A browser portal also supports changing a statement's user-visible note through a cookie-authenticated request. Notes can be supplied by tenant members.

Trace Bo's `GET /statements/s-9` from the browser to the database. Specify the trusted user and proxy workload identities, tenant inputs, decision and query constraint. For the API-to-database connection, specify transport, database server verification, the service's database identity and the behavior when required connection protection fails. Then propose controls at the network, storage and input/output boundaries for a copied backup, an injected record ID, a malicious note and a forged note change. Explain the consequence of a policy service failure and one cost or limitation of a selected control. Assume the design makes no immediate-revocation timing promise.

## Knowledge checks

### Q1

Ada has a valid access token for the payout API, but requests another tenant's record. Which decision remains before returning the row?

**Answer.** The service must determine whether Ada may perform the read on that actual record's tenant using trusted membership and policy data. A valid token establishes a suitable identity and API scope, while object authorization decides this record access.

### Q2

In a variant where the proxy authenticates the caller and passes `X-User` to the service, an Internet client supplies its own `X-User`. How should the boundary handle it?

**Answer.** The proxy removes client-supplied identity headers, authenticates the caller itself, derives the assertion from that verified authentication and forwards it over a protected, authenticated hop. The service accepts it only from the authorized proxy, a direct client cannot reach the header-trusting endpoint, and the service still authorizes the requested record.

### Q3

The request ID is `r-42' OR '1'='1`. What should a correctly bound query do with it, and what additional restriction is needed?

**Answer.** It treats the entire string as a value, rather than SQL syntax. Shape validation can reject it, and the query also needs an authorized tenant predicate. Binding the record ID alone does not establish access to the matching tenant.

### Q4

A copied backup is exposed, but its encryption keys are held by a separately controlled service. Which threat does this design address, and what remains necessary for an online read?

**Answer.** It makes the copied ciphertext insufficient by itself to read the backup when keys remain inaccessible. The online service must still authorize each record read because an authorized running service may decrypt and disclose plaintext.

### Q5

A note contains markup-like text and is displayed in an HTML text node. A separate cookie-authenticated form changes that note. Select controls for both paths.

**Answer.** Encode the note for HTML text using a suitable renderer. Validate a session-bound CSRF token on the state change, and authorize the mutation. These controls address distinct risks. Encoding must match the actual output context.

### Q6

A team proposes relying on a private subnet instead of checking user permissions in the API. Evaluate this decision and name a cost of enforcing the missing control.

**Answer.** Segmentation limits which network paths can reach the service, but it does not determine a user's entitlement to an individual tenant record. Enforce the record/action policy at the API and accept the policy dependency and added latency. If the service cannot establish permission, deny the read.

## Sample solution and rubric

**EX-1 sample.** The browser validates the proxy's HTTPS endpoint. The proxy strips untrusted identity headers and forwards the token over an authenticated encrypted connection to the API. The authenticated proxy is the forwarding workload. Under the assumed user-delegated token profile, the API validates the configured JWT signature and required claims including issuer, audience, expiration and scope, then uses the issuer-scoped subject as Bo's identity. It asks trusted policy data which tenants Bo may read. The API connects to the database using TLS, verifies the intended database server and authenticates using its own restricted database principal. If required transport or server verification fails, connection setup fails and it sends no query. It binds `s-9` and authorized tenant C into a query constrained by both record and tenant. The query returns no row, so the API returns its non-disclosing error without financial data. A membership failure also denies the read. Narrow database privileges and segment network access, while retaining the per-record API check.

Protect backups with encryption and separately authorized keys. Bind request values to prevent a record ID from becoming SQL syntax, and validate its business shape. Render notes with encoding for their destination context. For the cookie-authenticated mutation, validate a session-bound CSRF token and authorize the write. Use managed, limited credentials and exclude tokens and financial fields from audit logs. Key management and policy availability add operational dependencies, while encryption cannot prevent a compromised authorized endpoint from returning plaintext.

| Criterion | Points | Evidence for full credit |
| --- | --- | --- |
| Identity and record decision | 3 | Validates the token for this API, distinguishes its issuer-scoped user subject from the proxy workload, obtains trusted membership, scopes the query to tenant C, denies `s-9` and denies on unavailable policy. |
| Network and storage boundaries | 2 | Protects all three hops, handles proxy identity headers, requires TLS with intended database server verification and a distinct restricted database principal, fails connection setup on transport or verification failure, and scopes backup encryption and key access to the exposure threat. |
| Input and output | 3 | Binds values, identifies context-specific encoding and requires both CSRF validation and authorization for the cookie-authenticated mutation. |
| Decision and trade-off | 2 | Explains a control's benefit, operational cost and remaining failure boundary. |

Award partial credit for correct controls with an incomplete trace. Equivalent controls earn credit when they satisfy the stated boundary and failure behavior. A valid token, private network, parameterized query or encrypted database alone does not earn the object-authorization points.
