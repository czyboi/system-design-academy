# Source evidence for M06-L01

Checked 2026-11-14. The museum catalogue, capacity inputs and case examples are original teaching scenarios. The approved inventory and Story SDA-M06-L01 supply topic scope.

| Claim | Exact primary evidence | Applicability |
| --- | --- | --- |
| C1. Shared caching of authenticated HTTP responses is restricted. Vary selects request-header variants; directives constrain storage and reuse. Revalidation or explicitly permitted stale reuse may also permit reuse, and a cookie alone is not a general shared-cache prohibition. | IETF [RFC 9111 §§3.5, 4.1, 4.2](https://www.rfc-editor.org/rfc/rfc9111.html#section-3.5), [private and no-store directives](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2), [sensitive information](https://www.rfc-editor.org/rfc/rfc9111.html#section-7.3). | Verified for HTTP caches. Application key design needs its own access controls. |
| C2. PostgreSQL has shared database buffers and also relies on the OS cache. | PostgreSQL 18 manual [Resource Consumption, shared_buffers](https://www.postgresql.org/docs/18/runtime-config-resource.html#GUC-SHARED-BUFFERS). | Verified for PostgreSQL 18. No sizing or cache-hit guarantee. |
| C3. Redis Community Edition 7.4 supports lists and sorted sets, RDB snapshots and AOF persistence, and maxmemory policies. | Redis [LPUSH](https://redis.io/docs/latest/commands/lpush/), [ZADD](https://redis.io/docs/latest/commands/zadd/), [7.4.0 snapshot settings](https://github.com/redis/redis/blob/7.4.0/redis.conf#L391), [AOF settings](https://github.com/redis/redis/blob/7.4.0/redis.conf#L1302), [memory and eviction settings](https://github.com/redis/redis/blob/7.4.0/redis.conf#L1033), [version and license table](https://redis.io/legal/licenses/#about-past-licenses). | Verified for the named commands and configuration features. Persistence and eviction have separate settings and failure implications. |
| C4. Local and external caches differ in cold-start and sharing behavior. Coalescing can suppress repeated fills for one key; jitter spreads independent expiries. Rate, burst and concurrency are distinct controls. | AWS Builders' Library [Caching challenges and strategies, local/external caches and thundering herd](https://aws.amazon.com/builders-library/caching-challenges-and-strategies/), Nishtala et al. [Scaling Memcache at Facebook, §3.2.1](https://www.usenix.org/system/files/conference/nsdi13/nsdi13-final170_update.pdf#page=4), AWS [Cache Validity](https://docs.aws.amazon.com/whitepapers/latest/database-caching-strategies-using-redis/cache-validity.html), Google Cloud Tasks v2 [RateLimits](https://docs.cloud.google.com/tasks/docs/reference/rpc/google.cloud.tasks.v2#ratelimits). | Verified design mechanisms. A coalescer's scope and actual hit rate depend on deployment. |
| C5. Cache-aside misses load and populate. Read/write integration can use synchronous or deferred persistence and anticipatory refresh. | Microsoft [Cache-Aside pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/cache-aside#solution), Oracle Coherence 14.1.2 [Caching Data Sources, Selecting a Cache Strategy](https://docs.oracle.com/en/middleware/fusion-middleware/coherence/14.1.2/develop-applications/caching-data-sources.html). | Verified for these illustrated strategies. M06-L02 owns the detailed coherence and durability traces. |
| C6. Read Committed statements use a fresh snapshot; standby visibility depends on replay. An outbox persists a change and notification record together to recover delivery. | PostgreSQL 18 [Read Committed](https://www.postgresql.org/docs/18/transaction-iso.html#XACT-READ-COMMITTED), [hot standby visibility](https://www.postgresql.org/docs/18/hot-standby.html#HOT-STANDBY-USERS), AWS [transactional outbox motivation](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html#motivation). | Verified for PostgreSQL 18 and the documented outbox pattern. The generation protocol is a scenario design, with asynchronous staleness and duplicate-safe event processing. |
