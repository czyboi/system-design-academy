# Source evidence for M06-L02

Checked 2026-11-14. The status-record schedules, version fencing protocol and numbers are original models of specific implementation choices.

| Claim | Primary evidence | Applicability |
| --- | --- | --- |
| C1. Cache-aside lets the application handle reads and fills. A common write sequence commits to the data store before invalidating. | Microsoft [Cache-Aside, Solution and Considerations](https://learn.microsoft.com/en-us/azure/architecture/patterns/cache-aside#solution). | Verified pattern. This order closes the invalidate-first race and leaves a stale-fill race. |
| C2. Read-through places miss loading behind the cache interface. Write-through synchronously calls the backing store, while write-behind queues future store work. Refresh-ahead can schedule an early reload for an eligible entry. | Oracle Coherence 14.1.2 [Caching Data Sources](https://docs.oracle.com/en/middleware/fusion-middleware/coherence/14.1.2/develop-applications/caching-data-sources.html), sections Read-Through Caching, Write-Through Caching, Write-Behind Caching and Requirements, Refresh-Ahead Caching. | Verified for Coherence's cache-facing operations. The lesson's store-first write-through sequence and recovery contract are illustrative application choices. |
| C3. A stale fill can arrive after invalidation. A cache can fence late fills using a token checked at writeback. | Nishtala et al., NSDI 2013 [Scaling Memcache at Facebook, §3.2.1 Leases](https://www.usenix.org/system/files/conference/nsdi13/nsdi13-final170_update.pdf#page=4). | Verified example of one implementation. The lesson's transactional generation is a separate illustrative design. |
| C4. A new primary Read Committed statement reads from a statement-start snapshot. Conditional updates can recheck the predicate after a concurrent change. | PostgreSQL 18 [§13.2.1 Read Committed](https://www.postgresql.org/docs/18/transaction-iso.html#XACT-READ-COMMITTED), [§26.4.1 standby visibility](https://www.postgresql.org/docs/18/hot-standby.html#HOT-STANDBY-USERS). | Verified scope. The revision key, read-age deadline and failure response are application choices. |
| C5. An authoritative retry record can pair request identity and input with the business mutation. An evicted cache can lose previously observed version information. | AWS Builders' Library [Making retries safe with idempotent APIs](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/), Meta [Cache made consistent, cache invalidation race and eviction](https://engineering.fb.com/2022/06/08/core-infra/cache-made-consistent/). | Verified patterns. The example uses PostgreSQL authority and revision keys, and does not assume Meta's cache protocol. |
