# Source evidence for M06-INTEGRATION

Checked 2026-11-15 against the SDA-v1 module and scoped lesson evidence. All workload counts, cache performance limits and drill observations are illustrative.

| Design decision | Evidence and scope |
| --- | --- |
| Share a bounded query result with a complete key | M06-L01 compares location, key and granularity, including the cost of invalidating changes in membership. A public query can share results for the same locale, query parameters and source and rank versions. The drill's memory, hit distribution and permissions are scenario assumptions. [M06-L01 evidence](../evidence/M06-L01.md), [Microsoft Cache-Aside](https://learn.microsoft.com/en-us/azure/architecture/patterns/cache-aside#solution). |
| Bind hits and fills to an authoritative generation and a source deadline | In PostgreSQL 18 a fresh Read Committed statement on the primary uses a statement-start snapshot. Source data and generation must change in the same transaction for this example. Each successful attempt uses the generation obtained by its applicable authority check; affected-domain coverage and the independent ordered-content oracle are scenario contracts. The fill also binds the payload and revision to its actual read. [M06-L02 evidence](../evidence/M06-L02.md), [PostgreSQL 18, Read Committed](https://www.postgresql.org/docs/18/transaction-iso.html#XACT-READ-COMMITTED). |
| Route shards and protect the origin | Consistent hashing can limit reassignment when membership changes. The surviving cache's data, freshness and workload are separate questions. Coalesce matching fills and gate distinct queries, retries and warm-up at the same expensive origin. Budget lightweight generation reads separately. The 45/s saving is a conditional scenario assumption, not a sourced performance guarantee; refresh and recovery also consume the origin budget. [M06-L03 evidence](../evidence/M06-L03.md), [Scaling Memcache at Facebook, §3.2.1](https://www.usenix.org/system/files/conference/nsdi13/nsdi13-final170_update.pdf#page=4). |

The M06-L01 policy preview points to the overlapping reads, writes and recovery traces in M06-L02. The integration uses its authority-checked revision option and retains the asynchronous invalidation option for benign content where the contract permits delayed advancement. M06-S1 combines M06-L01-LO2, M06-L02-LO1 and M06-L03-LO2. The companion assessments retain each lesson's full outcome coverage.
