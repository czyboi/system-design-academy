# Companion assessment

## Practical exercise

**EX-1.** A museum releases a public exhibition map in English and French. The current URL `/map` returns a variant chosen by a `lang` query parameter. A pull CDN currently keys only on the path and keeps responses fresh for one hour. At 09:00, the museum publishes a correction. The first request at a cold edge occurs during an origin outage. A separate `/account/map` response includes a visitor's name.

In the first second of a separate release drill with the origin healthy, four cold edges each receive 300 requests across the same 40 distinct public keys. At each edge, all requests for a key overlap while its first fetch is in flight. Each edge collapses requests locally, and currently all four fetch directly from the origin. The map route has a budget of 100 origin fetches in that second. An optional shared upstream tier can coalesce across edges only when its requests overlap and use the same key.

Trace the language and outage failures. Propose a corrected key, replacement and origin-failure behavior for public and account routes. Compare origin fetches with local and ideal shared collapsing, then defend a release policy that respects the origin budget even if collapsing is incomplete. Specify a measurement at the origin boundary and a privacy test.

## Knowledge checks

### Q1

Why does the first request at edge B miss even after edge A has cached v1 in the worked example?

**Answer:** The example assumes independent cold edges.

**Explanation:** A stored copy at A does not establish a stored copy at B.

### Q2

At minute 3, a client still has catalogue metadata referencing `/launch-v1.jpg`. What can it request?

**Answer:** It can still request v1.

**Explanation:** Publishing v2 does not update metadata already held by the client.

### Q3

The origin fails and an edge has never stored v2. Can that edge serve a stale v2 copy from its cache?

**Answer:** No.

**Explanation:** Serving a stale response requires a previously stored eligible representation and a policy that permits its use.

### Q4

Why is a cache key that omits `size` unsafe for a public image endpoint whose response changes with `size`?

**Answer:** A request can receive the representation stored for another size.

**Explanation:** The cache cannot distinguish the variants using that key.

### Q5

When might proactive population suit a release, and what does it cost?

**Answer:** It can suit a predictable release with expected demand across regions, while using distribution and storage resources before requests arrive.

**Explanation:** Some populated copies may never be requested and provider capabilities differ.

### Q6

An origin sends `Cache-Control: no-store` for a personalized response through CloudFront. What configuration must also be checked?

**Answer:** Check the distribution's cache policy, including minimum TTL.

**Explanation:** A positive CloudFront minimum TTL can override origin directives, so the end-to-end configuration must enforce the desired privacy boundary.

## Answer key / rubric

With a path-only key, the first stored language can be returned to requests for the other language. Add `lang` to the key or use another correct variant mechanism. Publish a versioned corrected map URL and update referring metadata, while accounting for old metadata and cached references. A cold edge cannot serve the new version during origin failure without an available upstream or previously populated copy. During the outage, a request for an old map URL can receive a stale response for that same URL and matching language if the policy permits its age. A request for the corrected URL needs a matching cached response or a reachable upstream. Configure the account response as private or non-stored and verify that the CDN policy enforces this, including its minimum TTL. A shorter TTL trades more upstream refresh work for a shorter freshness window. A versioned URL may leave old references in clients until those references refresh.

During the drill, 1,200 viewer misses can collapse to 4 × 40 = 160 origin fetches with local-only collapsing. An ideal shared tier that fetches each key once cuts this to 40. If the tier is split into two independent groups that each fetch all keys once, the count is 80. These counts depend on key reuse and timing. An admission limit of 100 origin fetches over the modeled second protects capacity when requests split or retries add work, at the cost of deferring or rejecting some cold misses. Prepopulate popular keys or ramp traffic to reduce these rejections. Count fetch attempts, including retries, at the origin during a simultaneous four-edge cold start. During a separate outage drill, verify that absent variants fail in a controlled way, eligible stale variants obey the age rule and two signed-in users cannot receive each other's account map.

Score 10 points. Award 2 for the variant trace and replacement, 2 for distinguishing stale, absent and personalized responses, 2 for the two origin estimates with overlap assumptions, 2 for a defensible capacity policy and its trade-off, and 2 for tests of the origin limit and user isolation. Correct ideal arithmetic alone earns no capacity-policy credit. Accept other designs that satisfy the same constraints.
