# Source evidence for M02-INTEGRATION

Checked 2026-11-11. Confidence is verified for the scoped claim in each row. Scenario inputs, calculations and design judgments are original illustrative assumptions.

| Claim | Supported statement | Primary evidence and version | Scope and limits |
| --- | --- | --- | --- |
| DNS-1 | On a cache miss a recursive resolver can follow referrals to authoritative servers, follow an alias and cache records for their remaining TTL. | [IETF RFC 1034 §§3.6, 4.3.2 and 5.3.3 (1987)](https://datatracker.ietf.org/doc/html/rfc1034#section-5.3.3) | Caching is per record set and resolver. TTL applies to DNS data, separate from connection lifetime. |
| DNS-4 | Resolvers may use expired cached data when refresh fails under a configured serve-stale policy. | [IETF RFC 8767 §§4 and 5 (2020)](https://datatracker.ietf.org/doc/html/rfc8767#section-4) | Conditional extension. Do not use TTL as a universal deadline for migration. |
| NET-4 | HTTP/1.1 supports persistent connections, HTTP/2 multiplexes streams on TCP, and HTTP/3 uses QUIC streams over UDP. TLS 1.3 authenticates and encrypts within its connection assumptions. | [IETF RFC 9112 §9.3, RFC 9113 §5, RFC 9114 §2, RFC 9000 §2, RFC 8446 §1](https://datatracker.ietf.org/doc/html/rfc9114#section-2) | See [1.1](https://datatracker.ietf.org/doc/html/rfc9112#section-9.3), [2](https://datatracker.ietf.org/doc/html/rfc9113#section-5), [QUIC](https://datatracker.ietf.org/doc/html/rfc9000#section-2), [TLS](https://datatracker.ietf.org/doc/html/rfc8446#section-1). QUIC streams can still share congestion and application dependencies. |
| EDGE-1 | L4 routing can select upstream TCP/UDP flows without examining HTTP; address and port translation is one forwarding technique. HTTP-aware reverse proxying can select based on application data. | [NGINX Stream Proxy and HTTP Proxy modules (living), IETF RFC 3022 §2.2 (2001)](https://nginx.org/en/docs/stream/ngx_stream_proxy_module.html) | See [HTTP Proxy](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass) and [NAT](https://www.rfc-editor.org/rfc/rfc3022.html#section-2.2). Implementations may proxy separate connections or translate packets. |
| CDN-1 | A pull CDN serves a cached hit or asks an upstream tier/origin for a miss. A proactive population design pays upload/prefill and distribution cost before demand. | [AWS CloudFront Developer Guide, How CloudFront delivers content (living)](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/HowCloudFrontWorks.html) | The source covers the CloudFront pull example. Proactive population is an architecture alternative, without any claim of universal push or prewarm API. |
| CDN-2 | The cache key identifies request variants; freshness depends on age and applicable TTL. private prohibits shared storage and no-store prohibits storage under HTTP semantics. | [IETF RFC 9111 §§2, 3.2, 4.1, 4.2, 5.2.2 (2022)](https://datatracker.ietf.org/doc/html/rfc9111#section-5.2.2) | See [variant matching](https://datatracker.ietf.org/doc/html/rfc9111#section-4.1) and [CloudFront cache policy](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cache-key-understand-cache-policy.html). Check actual CDN settings; positive minimum TTL can override origin directives in CloudFront. |
| CDN-3 | Versioned object URLs and invalidation address different replacement needs. Edge invalidation cannot promise eviction from browsers and intermediary caches. | [AWS CloudFront Developer Guide, Update existing objects and Invalidate files (living)](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/UpdatingExistingObjects.html) | See [Invalidation](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Invalidation.html). Publishing new asset links also requires a freshness plan for their referring metadata. |
| CDN-4 | stale-if-error can permit eligible stale content during a specified error window. | [IETF RFC 5861 §4 (2010, Informational)](https://datatracker.ietf.org/doc/html/rfc5861#section-4) | Requires a prior cached representation and support/policy. Use only for deliberately shareable content with a stated freshness tolerance. |
