# Source evidence for M08-L02

Checked 2026-11-15. Window boundaries, lateness policy, thresholds and events in the teaching example are scenario assumptions.

| Claim | Primary evidence and scope | Verification and limits |
| --- | --- | --- |
| C1. Event time determines where a record belongs. Processing time determines when it is observed. Windows bound the logical grouping, triggers choose output timing, and a watermark estimates event-time progress. | Akidau et al., Google, VLDB 2015 [The Dataflow Model, §§2.1–2.3](https://www.vldb.org/pvldb/vol8/p1792-Akidau.pdf#page=2). | Verified terminology and trade-off. A watermark need not prove all earlier events have arrived. Define explicit provisional, update and final states for the scenario. |
| C2. Bounded state requires an explicit lateness and deduplication policy. A replayable source, durable progress/checkpoint and compatible sink determine the effect of retries. Watermark-based deduplication has a horizon. | Apache Spark 4.0.1 [Structured Streaming, Fault Tolerance Semantics](https://spark.apache.org/docs/4.0.1/streaming/getting-started.html#fault-tolerance-semantics) and [Structured Streaming Programming Guide, Streaming Deduplication and Watermarking](https://spark.apache.org/docs/4.0.1/streaming/apis-on-dataframes-and-datasets.html#streaming-deduplication). | Verified for the documented API. Distinguish duplicate input event IDs from reprocessing the same offsets. Engine guarantees depend on participating sources, sinks and output mode. Archived replay with a versioned replacement result is a scenario design. |
| C3. Space-Saving uses a fixed counter budget. On an untracked element when full it replaces a minimum counter and records an error bound. Near-tied estimated ranks can be uncertain. | Metwally, Agrawal and El Abbadi, UCSB [Efficient Computation of Frequent and Top-k Elements in Data Streams, increment-counters algorithm and error analysis](https://www.cs.emory.edu/~cheung/Courses/584/Syllabus/papers/Frequency-count/2005-Metwally-Top-k-elements.pdf). | Verified for insert-only unit increments; use one summary for the whole window in a worked trace. Do not assume unions of per-shard top-k are exact, or that expiration supports arbitrary deletions. Exact counts and baseline scores are scenario calculations. |
| C4. Storm Core 2.8.1 can track anchored tuple trees and acknowledge or fail a root. Replay depends on a spout that can re-emit and appropriate acknowledgements; external effects need a separate contract. | Apache Storm 2.8.1 [Guaranteeing Message Processing, fully processed and reliable spout sections](https://storm.apache.org/releases/2.8.1/Guaranteeing-message-processing.html). | Verified at-least-once processing under the stated conditions. This claim covers Core, with no Trident or universal sink guarantee. |
| C5. Spark Structured Streaming micro-batches update incremental query state, checkpoint offset progress and rely on compatible sink behavior on retry. | Apache Spark 4.0.1 [Structured Streaming introduction](https://spark.apache.org/docs/4.0.1/streaming/index.html) and [Programming model and fault tolerance](https://spark.apache.org/docs/4.0.1/streaming/getting-started.html#fault-tolerance-semantics). | Verified for the named mode and documentation. Compare execution and output boundaries with Storm without equating their delivery semantics. |
