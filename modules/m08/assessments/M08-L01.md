# Companion assessment for M08-L01

## Practical exercise

**EX-1.** A closed snapshot contains each sale once. Split A has `(a1, Art, 2)` and `(a2, Books, 3)`. Split B has `(b1, Art, 4)` and `(b2, Games, 3)`. Each mapper emits `(category, units)`. Job 1 sends Art and Games to R0 and Books to R1. The worker storing split B's intermediate file dies after the map reports completion. Assume deterministic tasks, private attempt files, one selected map output per split and one selected reducer output per logical reducer. A reducer discards invalidated contributions before committing. The final report orders by units descending and category ascending.

1. Show mapper output, grouped reducer input, and category totals after B is retried. Explain why the retry does not add the same contribution twice.
2. Specify a second job's ordering key and how to obtain one globally ordered result from more than one reducer. Give the final ranking.
3. Art becomes the dominant category in a larger snapshot. Propose a correct way to distribute its summation and state its extra cost. Explain the role of replicas and metadata when reading a lost worker's input.
4. The team also runs many iterative analyses of the same intermediate data. Compare a MapReduce-style batch, persisted Spark RDDs, and a database aggregation that already meets the deadline. Give a choice and the evidence needed to revisit it.

## Knowledge checks

### Q1

Which pairs does the Books reducer receive in the lesson's first job, and where do they come from?

**Answer.** It receives `(Books, 2)` from split A and `(Books, 3)` from split B. The partitioner assigns both to the same reducer, and shuffle fetches that reducer's partition from each selected map output.

### Q2

In the same example, split A's map output is lost and the map reruns. What must the reducer and publisher ensure to retain Books 5?

**Answer.** Use exactly one valid selected contribution for split A and one for split B, discarding any invalidated contribution before publication. Publish one winning result per reducer. Private attempt files and selection support this contract. They do not remove duplicates that were already in the source.

### Q3

Why do the sorted outputs of two hash-partitioned reducers fail to establish a global ranking?

**Answer.** Each file can be sorted internally while a higher-ranked key resides in either file. Globally ordered range partitions using the same comparator, read in range order, or a single reducer establish the required order.

### Q4

What is the benefit and limit of scheduling a map near a replica?

**Answer.** A local input read can avoid transferring that split across the network. Local slots may be busy, and the later shuffle still moves intermediate values where reducers need them.

### Q5

All Books records go to one slow reducer. Why might adding reducers fail, and when can salting help?

**Answer.** With unchanged key partitioning, Books still has one destination. Salt can distribute an associative sum across subkeys, followed by a second aggregation that removes the salt. It costs another stage and does not automatically work for a computation without a correct merge rule.

### Q6

What do an HDFS NameNode and DataNode each contribute, and when might persisted Spark RDDs be attractive?

**Answer.** In HDFS 3.4.2 the NameNode manages namespace and block mapping, while DataNodes store and serve block data. A surviving replica needs a usable metadata and access path. Persisted RDDs can help when repeated iterations reuse intermediate partitions and resources justify their retention and possible recomputation. Spark can still shuffle.

## Reference solution and rubric

Split A emits `(Art, 2)` and `(Books, 3)`. Split B emits `(Art, 4)` and `(Games, 3)`. After the replacement B output is selected, R0 groups Art `[2, 4]` and Games `[3]`, while R1 groups Books `[3]`. Their totals are Art 6, Games 3 and Books 3. The invalidated B output contributes no additional values to the committed result.

Job 2 emits keys `(-6, Art)`, `(-3, Books)` and `(-3, Games)`. For example, an assumed range boundary `(-3, "D")` places Art and Books in the first range and Games in the second. Each range is sorted with the composite comparator, and the client reads range files in order. The final ranking is Art 6, Books 3, Games 3. A single reducer is also correct.

For the larger input, distribute Art records deterministically among salted subkeys, sum each and recombine the partial sums before sorting. This adds an aggregation stage and intermediate traffic. A surviving input replica can supply data after a host failure if the metadata and read path are available. The NameNode's metadata role remains a separate availability concern. An RDD workflow may fit repeated reuse if persistence and recovery costs fit the resource budget. A database query that meets the deadline avoids introducing a distributed batch stack. A large one-pass snapshot with a bounded deadline may favor batch. Measure scan time, shuffle volume, skew, reuse and resource pressure before choosing.
