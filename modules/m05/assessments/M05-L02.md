# Companion assessment for M05-L02

## Practical exercise

**EX-1.** An industrial portal reads 30 minutes of readings for a meter and suggests accounts two hops away along directed follows. One meter dominates writes. A sensor correction may coexist with the old value for audit. A graph seed A follows B and C. B follows D and E, C follows D and A. Exclude the seed and direct follows. During a separate drill, one first-hop neighbor has 50,000 edges and lives on another partition.

Choose a row key and model for meter readings. Trace the half-open UTC interval [2026-11-13 23:45:00, 2026-11-14 00:15:00) if meter `device-18` uses four buckets. Show the bounds for one bucket and distinguish event time from stored correction version. Compare the relevant version model with Cassandra. Trace the graph candidates and choose behavior when the remote supernode cannot be exhaustively expanded under the interactive budget.

## Knowledge checks

### Q1

Why can a timestamp-first Bigtable key make new writes hot?

**Answer.** Adjacent new timestamps concentrate in the newest lexicographic range, giving its owner most writes.

### Q2

With four buckets and the specified half-open interval across midnight, how many Bigtable ranges are needed for `bucket#device#day#time#eventId`?

**Answer.** Four. Within each bucket and device prefix the two fixed-width days are contiguous, so one range spans midnight. Merge the four ranges.

### Q3

Which second-hop results survive exclusions and deduplication in the stated graph?

**Answer.** D and E. D appears through both neighbors, and A is excluded as the seed.

### Q4

Can Bigtable garbage-collection eligibility alone enforce that an old correction never appears in reads?

**Answer.** No. It can remain readable until compaction. Apply the query's explicit version or time filter.

### Q5

Can a Cassandra mutation timestamp alone provide queryable correction history?

**Answer.** No. It participates in conflict resolution. Model historical corrections as separately keyed records.

### Q6

Why does an indexed seed fail to bound the entire two-hop traversal?

**Answer.** The index locates the seed. Neighbor degree and remote adjacency determine subsequent work.

## Sample solution and rubric

Use `bucket#device#day#time#eventId`, with fixed-width UTC fields and a full immutable event ID. Derive the bucket from that ID and reuse the same row for corrections. Distinct events at the same time have distinct rows. For bucket 0 the lower-inclusive bound is `0#device-18#20261113#234500#` and the upper-exclusive bound is `0#device-18#20261114#001500#`. Repeat for buckets 1–3 and merge the four ranges by event time and event ID.

Keep the event time in the key and use distinct cell-version timestamps at valid millisecond granularity for corrections. Configure retention to cover the required audit period and correction volume. An audit read requests the retained versions for the required version-time interval, while the latest-value path deliberately requests the newest version. A Cassandra alternative clusters event rows within `(meter, day, bucket)`, addresses each day and bucket partition, and models queryable correction history as separate entries.

Look up A by indexed ID, expand B and C, and return D and E. Bound the expansion by edges, remote requests or the interactive deadline. A response that does not exhaust the graph must expose truncation, or use a separate asynchronous exhaustive contract. Measure remote reads and edges examined with high-degree and ordinary seeds before deciding placement.

| Criterion | Points | Full credit |
| --- | ---: | --- |
| Wide-column route | 3 | Explains stable event identity and bucket, write skew, four bounded cross-midnight ranges and merge. |
| Versions and product scope | 2 | Distinguishes event time, valid cell-version timestamps, audit retention and read filtering from Cassandra conflict timestamps and day-partition routing. |
| Graph trace | 3 | Computes correct results and separates indexed seed from adjacency and remote work. |
| Decision and failure behavior | 2 | Bounds expansion, preserves an honest completeness contract and proposes measurable comparisons. |

Award partial credit for correctly explained mechanisms with incomplete traces. Accept alternatives that meet the same constraints.
