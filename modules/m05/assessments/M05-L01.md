# Companion assessment for M05-L01

## Practical exercise

**EX-1.** An outdoor store validates session tokens, shows a product detail page and lists active boots in a category under a price threshold. Every validation whose authoritative check begins after a confirmed revocation must deny that token. A check overlapping revocation may have observed active before the revocation commits. A cache may lose entries or contain an old positive result. Product browse can lag, while one product's price and bounded set of display labels must change together. During a migration, old readers and writers use top-level `price` and new readers can decode a nested price.

Propose a model and access path for each operation. Trace session cache loss and the stale positive result, one product price change across the threshold, and coexistence of old and new documents without dropping browse results. State a freshness or transaction question to verify for each product option.

## Knowledge checks

### Q1

Why can a token lookup route before knowing the user's account ID?

**Answer.** The token derives the session key. The account relationship is a field of the returned value.

### Q2

What must change when a product indexed by category and encoded price moves from 72 to 84?

**Answer.** The old access-path entry must be removed or invalidated and the new one added under the index's consistency contract. A product ID alone cannot answer the category range query.

### Q3

Which read needs extra work if the field indexed as `price` moves to a nested path?

**Answer.** Browse using the old indexed path can miss nested-only documents. Keep top-level `price` present and authoritative while old readers or writers remain. A dual-path query helps only readers that have been updated to use it. After old writers retire, compatible writers can atomically maintain both fields while the new path is backfilled and verified.

### Q4

Should a positive cache entry by itself authorize a session when every authoritative check begun after confirmed revocation must deny?

**Answer.** No. Check the authoritative state with the required consistency. For example, use a strongly consistent base-table read in the same DynamoDB region where revocation was written. A check that read active before a concurrent revocation committed can finish afterward. An unavailable authority fails closed.

### Q5

When would embedding product variants stop being a good fit?

**Answer.** An unbounded or independently owned set can make the document expensive to update and read. Give it a separate access path and define the relationship.

### Q6

Can a DynamoDB global secondary index be asked for a strongly consistent read?

**Answer.** No. Use the documented eventual GSI semantics or choose an eligible table or local index access path if the requirement permits it.

## Sample solution and rubric

Look up a hash-derived session key. Store revocation in a single-region DynamoDB base table and acknowledge it after the write succeeds. Use cache results as hints. A same-region base-table `GetItem` with `ConsistentRead=true` started after that confirmation sees the revoked state and denies even if a positive cache entry remains. A missing cache entry also leads to the authoritative check. If that authority is unavailable, fail closed. A check that observed active before the revocation committed may finish afterward. A stronger requirement on the protected action itself needs coordinated admission.

Store product price and bounded labels in one document and update it atomically. Use a category, active-status and price index for browse, verify the plan and define how stale reads are exposed. A price of 84 stops matching the under-80 query once the chosen read path includes that change. Keep top-level `price` present and authoritative while old readers or writers remain. Upgrade or retire old writers before relying on a nested copy. Compatible writers then update both fields atomically, and the team backfills and verifies nested values before migrating readers and retiring the old field and index. A composite-key listing can partition by category and active status and order by price if it protects or repairs the separately maintained entries.

| Criterion | Points | Full credit |
| --- | ---: | --- |
| Session access and revocation | 3 | Routes exact keys, traces stale positive and unavailable authority, names a read eligible for the post-confirmation contract and distinguishes an overlapping validation from coordinated protected-action admission. |
| Product access and update | 3 | Traces the attribute query and one aggregate update, and states the visibility contract for browse. |
| Migration | 2 | Keeps top-level price authoritative while old readers or writers remain, then coordinates dual writes, backfill, verification and retirement of old dependencies. |
| Contract and trade-off | 2 | Distinguishes application semantics from selected product guarantees and identifies meaningful verification questions. |

Award partial credit for correctly explained mechanisms with incomplete traces. Accept alternatives that meet the same constraints.
