# Source evidence for M05-L02

Checked 2026-11-13. Confidence is verified for the scoped claims below. Worked scenarios and design calculations are original and use illustrative assumptions.

| Claim | Supported mechanism | Primary evidence | Limits |
| --- | --- | --- | --- |
| Wide rows and versions | Bigtable row keys sort lexicographically, families group columns and cells can have timestamped values. Family garbage collection configures retention by age or version count. | [Google Cloud Bigtable schema design](https://docs.cloud.google.com/bigtable/docs/schema-design), [garbage collection](https://docs.cloud.google.com/bigtable/docs/garbage-collection), [Chang et al., Bigtable, OSDI 2006 §2](https://www.usenix.org/legacy/event/osdi06/tech/chang/chang.pdf#page=2) | Compaction can lag logical retention. Filter reads explicitly when the contract needs it. |
| Ranges and granularity | The Bigtable data API supports inclusive starts and exclusive ends for byte-ordered row ranges. Explicit mutation timestamps must match the table's granularity. | [Bigtable Data RPC RowRange and Mutation.SetCell](https://docs.cloud.google.com/bigtable/docs/reference/data/rpc/google.bigtable.v2) | The stable event ID and fixed-width time encoding belong to the example. A range may cross midnight within one bucket. |
| HBase and Cassandra | HBase models cells with timestamped versions and family settings. Cassandra distributes by partition key, orders within partitions by clustering columns and reconciles normal writes by timestamp. | [Apache HBase Reference Guide, Data Model](https://hbase.apache.org/book.html#datamodel), [Apache Cassandra CQL DDL, primary key](https://cassandra.apache.org/doc/latest/cassandra/developing/cql/ddl.html), [Cassandra architecture, Dynamo](https://cassandra.apache.org/doc/latest/cassandra/architecture/dynamo.html) | Cassandra write timestamps do not expose Bigtable-style retained cell-version histories. |
| Traversal | Neo4j supports bounded path matching and uses indexes to help locate starting nodes. Traversal work depends on graph shape and predicates. | [Neo4j Cypher Manual, variable-length paths](https://neo4j.com/docs/cypher-manual/current/patterns/variable-length-paths/), [indexes](https://neo4j.com/docs/cypher-manual/current/indexes/performance-indexes/using-indexes/) | The distributed placement and fan-out example is a design model, independent of Neo4j deployment behavior. |
