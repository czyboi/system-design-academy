# Source evidence for M05-L01

Checked 2026-11-13. Confidence is verified for the scoped claims below. Worked scenarios and design calculations are original and use illustrative assumptions.

| Claim | Supported mechanism | Primary evidence | Limits |
| --- | --- | --- | --- |
| Keyed access | Redis GET retrieves the value for a string key and ZRANGE reads ranges of an explicitly maintained sorted set. Memcached basic text commands provide keyed access and expiry. | [Redis GET](https://redis.io/docs/latest/commands/get/), [Redis ZRANGE](https://redis.io/docs/latest/commands/zrange/), [Memcached Basic Text Protocol](https://docs.memcached.org/protocols/basic/) | Commands describe access and expiration. They do not imply a generic durability or failover policy. |
| Document aggregate | MongoDB describes embedding related data, referencing separately accessed data, and single-document write atomicity. Schema versions can coexist. | [MongoDB 8.0 data modeling](https://www.mongodb.com/docs/v8.0/data-modeling/best-practices/), [atomicity](https://www.mongodb.com/docs/v8.0/core/write-operations-atomicity/), [schema versioning](https://www.mongodb.com/docs/v8.0/data-modeling/design-patterns/data-versioning/schema-versioning/) | Cross-document operations and index design require separate evaluation. |
| Partition and sort key | DynamoDB groups items that share a partition-key value and orders by sort key for a composite primary key. Secondary indexes expose additional key access paths. | [AWS DynamoDB, core components, primary key and secondary indexes](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.CoreComponents.html), [read consistency](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadConsistency.html) | This is scoped to DynamoDB APIs and the chosen table or index. |
| Session authority | DynamoDB `UpdateItem` changes one item and a base-table `GetItem` with `ConsistentRead=true` reflects prior successful writes in the same Region. | [AWS DynamoDB UpdateItem](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_UpdateItem.html), [GetItem](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_GetItem.html), [read consistency](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadConsistency.html) | This supports a check starting after a confirmed revocation on the same authority. A check that overlaps the revocation has a different timing contract. |
| Indexed browse | MongoDB's ESR guidance puts equality fields before range fields in a matching compound index. DynamoDB Query requires equality on the partition key and permits a sort-key condition. | [MongoDB 8.0 ESR guideline](https://www.mongodb.com/docs/v8.0/tutorial/equality-sort-range-guideline/), [DynamoDB Query key conditions](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Query.KeyConditionExpressions.html) | Index selection and cost require workload evidence. The product model chooses how to represent active membership. |
