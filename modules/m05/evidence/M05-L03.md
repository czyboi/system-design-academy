# Source evidence for M05-L03

Checked 2026-11-13–14. Confidence is verified for the scoped claims below. Worked scenarios and design calculations are original and use illustrative assumptions.

| Claim | Supported mechanism | Primary evidence | Limits |
| --- | --- | --- | --- |
| Dynamo replication | The Dynamo paper uses version vectors and reconciliation, configurable N/R/W, fallback placements with hinted handoff and Merkle-tree anti-entropy. | [DeCandia et al., Dynamo, SOSP 2007 §§4.4–4.7](https://www.allthingsdistributed.com/files/amazon-dynamo-sosp2007.pdf#page=6) | Sloppy quorum may use different responding sets. The design does not establish current DynamoDB API behavior. |
| DynamoDB semantics | AWS scopes strongly consistent reads and transaction APIs by operation and resource, with transaction items limited to one AWS account and Region. | [AWS DynamoDB, read consistency](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadConsistency.html), [transactions](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis.html) | Single-Region transaction scope does not guarantee atomic visibility in another Region or on every index or stream. |
| Application receipt | A DynamoDB single-Region transaction can apply conditions on its update and put actions. A strongly consistent base-table read can find committed receipts. AWS documents a 10-minute request-token validity window. | [AWS DynamoDB transactions and idempotency](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis.html), [GetItem](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_GetItem.html) | The input-bound receipt and the scenario's longer retry window belong to the application. Absence alone cannot exclude in-flight work. |
| Spanner | The Spanner paper describes TrueTime and commit wait. Cloud Spanner documents externally consistent serializable transactions and a strong read mode. | [Corbett et al., Spanner, OSDI 2012 §4.2](https://www.usenix.org/system/files/conference/osdi12/osdi12-final-16.pdf#page=7), [Cloud Spanner isolation levels](https://docs.cloud.google.com/spanner/docs/isolation-levels), [timestamp bounds](https://docs.cloud.google.com/spanner/docs/timestamp-bounds) | Scope the selected mode and placement. The paper's mechanisms do not imply a workload-level latency target. |
| Transaction boundary | A relational transaction can group changes as a unit, with visibility and durability under the configured contract. | [PostgreSQL 18 transactions](https://www.postgresql.org/docs/18/tutorial-transactions.html), [M04-L01 order evidence](../../m04/evidence/M04-L01.md) | The basket, inventory and ranking division is a design example. Retail guarantees depend on exact operations, placement and failure assumptions. |
