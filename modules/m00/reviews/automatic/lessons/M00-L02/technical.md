## Technical findings

- **M00-L02-T2 · major · open.** The [lesson's load-test method](../../../../lessons/M00-L02.md#estimate-measure-and-revise) calls for successful response latency and errors, but its [host-failure example](../../../../lessons/M00-L02.md#worked-example) and the [companion's sample and scoring](../../../../assessments/M00-L02.md#answer-key--rubric) leave “reads must continue” without a measurable acceptance boundary. A test counting only reads that reach the survivor can report usable capacity and a fast tail while routing or admission drops most original reads. Give the worked example a clearly hypothetical client-observed success target over a fixed interval starting when the host is removed. Define all offered original valid reads as the denominator, define timely completion from client send through receipt of the requested report, and count rejections, errors, timeouts and late results as unsuccessful. Count deliberate revoked-link probes separately as a correctness check. Keep survivor capacity and successful-read latency as separate diagnostic measures. Require equivalent evidence in EX-1 and its rubric while allowing justified targets. [Google SRE Workbook, Implementing SLOs, What to Measure and SLI Specification vs SLI Implementation](https://sre.google/workbook/implementing-slos/#what-to-measure-using-slis).
- **M00-L02-T1 · minor · open.** The [deep dive](../../../../lessons/M00-L02.md#draw-the-paths-and-choose-a-deep-dive) and [trade-offs](../../../../lessons/M00-L02.md#trade-offs-and-failure-modes) correctly assume that every read reaches the check. For the HTTP example, make clear how the design keeps that assumption true after adding a content cache. A browser or intermediary can reuse a fresh successful GET response without origin validation, including on a new request after revoke confirmation. Authorization of a new read must precede release of report bytes even when those bytes are cached behind the application. A protected response can use `Cache-Control: no-store` from the start for compliant HTTP caches, or another design can show how authorization is enforced on reuse. Verify by making an allowed read, revoking the link, waiting for confirmation, and repeating the same URL through the actual client/edge path while it could still be cached. Previously saved copies and an already authorized transfer are separate scope decisions. This refines the archived finding with the concrete client boundary. [RFC 9111 §4](https://www.rfc-editor.org/rfc/rfc9111.html#section-4) · [RFC 9111 §5.2.2.5](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.5).
