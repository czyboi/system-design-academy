# Primary architecture-family evidence — M13-L01

Source check: 2026-11-16. **Historical** research papers are evidence for their own dated implementations and stated assumptions, **not** current commercial/product guarantees. The nightly-report case and all numbers, identities and diagrams are original synthetic examples. No third-party figures, code or prose are reproduced.

| Family / dated primary source | Bounded mechanism | Limit |
| --- | --- | --- |
| MapReduce — Dean & Ghemawat, 2004, OSDI, [Google Research](https://research.google/pubs/mapreduce-simplified-data-processing-on-large-clusters/) | Map/intermediate grouping/reduce, worker scheduling and failure handling | 2004 Google cluster, not 2026 managed service benchmark |
| Spark RDD — Zaharia et al., 2012, NSDI, [USENIX](https://www.usenix.org/conference/nsdi12/technical-sessions/presentation/zaharia) | Partition lineage and recomputation, optional reuse of memory-resident data | Reuse benefit depends on iterative workload; no generic speed guarantee |
| Bigtable — Chang et al., 2006, OSDI, [Google Research](https://research.google/pubs/bigtable-a-distributed-storage-system-for-structured-data/) | Sparse sorted mapping, row partition/locality | Historical Bigtable not the exact current HBase/Cassandra contract |
| Dynamo — DeCandia et al., 2007, SOSP, [Amazon Science](https://www.amazon.science/publications/dynamo-amazons-highly-available-key-value-store) | Availability with versioned conflicts under some failures | Not a DynamoDB 2026 API source |
| Spanner — Corbett et al., 2012, OSDI, [Google Research](https://research.google/pubs/spanner-googles-globally-distributed-database/) | Coordinated transactions and TrueTime uncertainty handling | Not simple wall-clock LWW or universal external system guarantee |
| GFS — Ghemawat et al., 2003, SOSP, [Google Research](https://research.google/pubs/the-google-file-system/) | Large-file, append-centric, failure-aware chunk storage | Historical workload and copying permissions; no pasted diagrams |
| ZooKeeper — Hunt et al., 2010, USENIX ATC, [USENIX](https://www.usenix.org/conference/usenix-atc-10/zookeeper-wait-free-coordination-internet-scale-systems) | Replicated coordination interface and order assumptions | Not tracing or Kafka log semantics; application writes need fencing |
| Chubby — Burrows, 2006, OSDI, [Google Research](https://research.google/pubs/the-chubby-lock-service-for-loosely-coupled-distributed-systems/) | Coarse lock/metadata service and leases | Cannot guarantee stale external writes prevented without integration |
| Dapper — Sigelman et al., 2010, [Google Research](https://research.google/pubs/dapper-a-large-scale-distributed-systems-tracing-infrastructure/) | Distributed trace observation | Does not enforce ownership |
| Kafka — current [Apache design docs](https://kafka.apache.org/documentation/#design) | Retained partitioned log under version-specific controls | Not a generic lock authority or full transactional DB |
| Redis/Memcached — [M11-L09 evidence](../../m11/evidence/M11-L09.md) | Durable-option versus disposable-cache contract | Upstream MS07 unmerged; version/configuration-specific |
| Storm — [Apache Storm docs](https://storm.apache.org/releases/current/index.html) | Stream/topology architecture for ongoing event processing | Exact release, guarantee and checkpoint mode must be checked before concrete claims |

HBase, Cassandra, MongoDB, DynamoDB and contemporary Spark/Storm behavior deliberately remain **version-scoped verification tasks** if selected for production. A company blog/catalog is a discovery pointer; before making a guarantee, independently verify the primary current source. Primary papers may limit diagram/code reproduction rights.
