# Consistency and partition decisions assessment

## Practical exercise

**EX-1.** A two-region service stores a public shipping label and a payment balance as separate objects. The label may show an older value if identified as such. A user must see their own completed label edit before a subsequent session read succeeds. A balance read used to approve a payment must be linearizable. The regions cannot communicate, and the second region lacks the latest label version and cannot reach the balance authority.

Trace the permitted responses for a public label read, the author's session read and the balance read. Explain the availability cost and state a conflict rule and a condition for eventual convergence. Describe one test after connectivity returns.

## Knowledge checks

### Q1

A write of `blue` completes, then a nonoverlapping read returns the earlier `green` with no intervening write. What does the history establish?

Answer: It violates linearizability for the object. It can be allowed by a weak or eventual consistency contract.

Explanation: The completed write must precede the later read in a linearizable history. A single result does not establish whether replicas will eventually converge.

### Q2

A read starts before a write completes and returns the previous value. Can the history be linearizable?

Answer: Yes, if the overlapping read can be ordered before the write and the rest of the object history permits that order.

Explanation: Linearizability preserves real-time order between nonoverlapping operations and permits a legal ordering of overlapping operations.

### Q3

In the worked partition example, why does the author's request wait or fail at region B?

Answer: B has version 6 and the session requires at least version 7.

Explanation: Returning the older version would violate the specified read-your-writes contract. Waiting, reaching a qualifying replica, or declining preserves it.

### Q4

What does CAP availability require at a non-failing node in the stated model, and what does an error mean for the requested operation?

Answer: Every received request must eventually get a valid response. Declining the operation gives up CAP availability for that request.

Explanation: The model's per-request property differs from a measured monthly request-success percentage.

### Q5

Both isolated regions accept edits to the same field. What must happen before the replicas can converge on a resolved value?

Answer: The relevant updates must propagate and replicas must apply a compatible deterministic resolution rule, or the application must resolve the conflict explicitly.

Explanation: Transporting both edits does not itself determine which value should survive. A selection rule can discard an edit.

### Q6

Why is a local strongly consistent read of an Amazon DynamoDB global table in version 2019.11.21 MREC mode insufficient evidence that a remote Region's newest write has arrived?

Answer: Cross-Region item replication in this mode is asynchronous.

Explanation: The local read's scope is the local replica. A remote change can still be in transit.

## Answer key / rubric

A defensible answer lets the public label read return the older identified label. The author read waits, reaches a replica with the required version, or declines. The balance read declines or waits until the authoritative path can meet its contract. The latter two choices reduce successful responses during the split. After recovery, a deterministic field-resolution rule and eventual delivery of the relevant updates allow convergence. A suitable test writes a label in one region, partitions the link, checks the session behavior at the older replica, heals the link, and verifies the resolved value and session read.

Award up to 4 points, one each for the public response, session guarantee, balance guarantee and availability trade-off, and convergence rule plus recovery test. Accept equivalent policies that satisfy the stated contracts and explain their costs.
