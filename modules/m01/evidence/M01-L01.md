# Evidence for M01-L01 — Capacity and latency budgets

Checked 2026-11-12. The activity feed and assessment use original model inputs. The approved [outline](../../../curriculum/revision-1/CURRICULUM_MASTER.md#m01-l01) and [coverage map](../../../curriculum/revision-1/coverage.csv) assign the estimate and timing topics to this lesson.

| ID | Claim | Exact source and applicability | Status |
| --- | --- | --- | --- |
| CL-01 | Plan capacity against forecast demand and validate the resource-to-capacity relation with load tests. Model average rate as activity × operations per activity ÷ seconds in the same interval. Estimate peak from a declared multiplier or measured peak window. | Google, *Site Reliability Engineering* (2016), [Demand Forecasting and Capacity Planning](https://sre.google/sre-book/introduction/#demand-forecasting-and-capacity-planning). Planning and measurement guidance. The time and peak arithmetic follows from the workload assumptions. State whether the high case combines correlated factors. | Verified |
| CL-02 | A byte is eight bits. SI MB and GB use powers of ten. MiB and GiB use powers of two. Bandwidth units follow from bytes per payload × requests per second × eight bits per byte. | NIST, [Prefixes for binary multiples and examples and comparisons with SI prefixes](https://physics.nist.gov/cuu/Units/binary.html). Definitions apply across products. Bandwidth is payload-only until headers, retransmission and replication are included at the specified interface. | Verified |
| CL-03 | Fixed daily ingestion × retention days × bytes per item estimates logical live data after the window fills. Full copies, separately stated index/metadata overhead and deliberate provisioning margin increase physical capacity. For a working-set estimate count distinct referenced items in the selected interval. | Storage formula is dimensional reasoning under fixed ingestion, uniform sizes, complete expiration and full copies. Peter Denning, *The Working Set Model for Program Behavior*, CACM 11(5), 1968, [§3 and Figure 2](https://denninginstitute.com/pjd/PUBS/WSModel_1968.pdf#page=4) define distinct recently referenced pages. Applying this to feed records is an analogy and requires an explicit access pattern. Duplicate reads add traffic without adding distinct objects. | Verified within model |
| CL-04 | A dependent chain serializes wait and work. Independent calls can overlap with enough concurrency. Sequential I/O accesses adjacent blocks and can benefit from locality and prefetch. Scattered accesses and cache misses change the latency and bandwidth picture. | David Patterson, *Latency Lags Bandwidth*, CACM 47(10), 2004, [pp. 71–75, Table 1 and practical implications](https://pages.cs.wisc.edu/~markhill/restricted/cacm2004_latency.pdf). Historical context and mechanisms. Jens Axboe et al., fio documentation 3.43-22-gd645, [I/O type](https://fio.readthedocs.io/en/latest/fio_doc.html#i-o-type), distinguishes sequential and random workloads for measurement. Keep block size, queue depth, cache and device conditions explicit. No device timing guarantee follows. | Verified |
| CL-05 | Use order-of-magnitude estimates to choose measurements. A single traced request can be budgeted by its critical path. End-to-end tail targets require measured latency distributions under representative load and can be obscured by averages. | Google, *Site Reliability Engineering* (2016), [Worrying About Your Tail](https://sre.google/sre-book/monitoring-distributed-systems/#worrying-about-your-tail-or-instrumentation-and-performance). Historical timing context in Patterson, above. Any sample ns, µs and ms values should be labeled assumptions. | Verified |
