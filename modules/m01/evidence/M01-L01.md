# Evidence for M01-L01 — Capacity and latency budgets

Checked 2026-11-11. Workload, timings and limits in the lesson are explicitly hypothetical.

| ID | Claim | Publisher, version and section | Scope and confidence |
|---|---|---|---|
| CAP-01 | Forecast growth and event spikes separately. Use representative load tests to validate resources against response targets. | Google, *Site Reliability Engineering* (2016), Chapter 1, [Demand Forecasting and Capacity Planning](https://sre.google/sre-book/introduction/#demand-forecasting-and-capacity-planning). | Verified. Peak and margin multipliers are scenario assumptions. |
| CAP-02 | KiB, MiB and GiB are successive powers of 1024 bytes. SI prefixes are decimal and a byte contains eight bits. | NIST, [Prefixes for binary multiples](https://physics.nist.gov/cuu/Units/binary.html), examples and comparisons, citing the IEC's 1998 adoption. | Verified. Retention × daily ingest × stored bytes × full copy count derives payload storage under constant ingest. Account separately for indexes, logs, backups and slack. |
| CAP-03 | The working-set idea uses distinct referenced units within a window. A service cache estimate can apply that idea to distinct objects in a wall-clock window. | Peter J. Denning (1968), [The Working Set Model for Program Behavior, definition and Figure 2](https://denninginstitute.com/pjd/PUBS/WSModel_1968.pdf#page=4). | Verified for the formal paging model. The service estimate is an analogy and excludes cache overhead. |
| CAP-04 | Resource latency and bandwidth can evolve at different rates. I/O benchmarks need access-pattern and configuration controls, such as request size and queue depth. | David Patterson, *Latency Lags Bandwidth*, CACM 47(10), 2004, [p. 71 and Table 1](https://pages.cs.wisc.edu/~markhill/restricted/cacm2004_latency.pdf). fio 3.43-22-gd645, [§1.13.6 I/O type and §2.2 Latency profile](https://fio.readthedocs.io/en/latest/fio_doc.html). | Verified. Historical measurements illustrate the distinction. Current latency values and ratios require deployment measurements. |
| CAP-05 | Dependent calls on the same critical path accumulate elapsed time. Independent eligible requests can sometimes overlap. | IETF, RFC 9112 (2022), [§9.3.2 Pipelining](https://www.rfc-editor.org/rfc/rfc9112.html#section-9.3.2). | Verified for HTTP/1.1 pipelining. Serial elapsed-time addition follows from the modeled dependency. End-to-end percentiles need end-to-end measurements. |
