# Evidence for M01-L02 — Performance versus scalability

The learner uses the workload and latency budgets from M01-L01. This draft applies those budgets to scaling decisions and request-path measurement.

## Topic and asset register

- PR-H032 and PR-H034 are assigned to “Measure the request and the workload.” Topic discovery uses Donne Martin's [The System Design Primer at the pinned revision](https://github.com/donnemartin/system-design-primer/blob/ae9bbd7b02d90b9866215de185217d33f39ab733/README.md#L412-L433), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). The lesson prose, Mermaid diagram, exercise and workload assumptions were created for this pilot.
- The historical [milestone PR](https://github.com/czyboi/system-design-academy/pull/28) and its [technical findings](https://github.com/czyboi/system-design-academy/blob/e823c8d72e59f1691ce7bfc65f37c209066eca99/modules/m01/reviews/M01-L02/technical.md) flag two relevant details. State which topology supplies enough work to saturate a shared dependency and define the population for latency percentiles. The current scenario and formulas use explicit boundaries for both.
- Numerical values are hypothetical. The fluid model uses an initially empty queue, fixed arrivals and service rates per interval, FIFO within a queue and negligible routing overhead. The store accepts overlapping calls without blocking the modeled CPU slots. The model can locate sustained overload under these assumptions. Application latency distributions, cost and effective capacity require measurement.
