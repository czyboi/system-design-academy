# Evidence for M01-L02 — Performance versus scalability

Checked 2026-11-11. The server capacities, burst and shared limit are original model inputs.

| ID | Claim | Publisher, version and section | Scope and confidence |
|---|---|---|---|
| PERF-01 | Performance is measured for a particular allocation and workload. Scalability describes how supported work changes with added resources, or how behavior changes along a named growth axis. | Werner Vogels (2006), [A Word on Scalability, opening discussion](https://www.allthingsdistributed.com/2006/03/a_word_on_scalability.html). Google, *Site Reliability Engineering* (2016), [The Four Golden Signals](https://sre.google/sre-book/monitoring-distributed-systems/#xref_monitoring_golden-signals). | Verified. Compare useful throughput at a common latency and error target and hold workload mix fixed for a resource comparison. |
| PERF-02 | Vertical scaling adds capacity to an instance. Horizontal scaling can increase capacity if traffic distributes and dependent resources can support it. Session placement can limit redistribution. | Microsoft Azure Architecture Center, [Autoscaling, Application design considerations](https://learn.microsoft.com/en-us/azure/architecture/best-practices/auto-scaling#application-design-considerations), web guidance. | Verified as design guidance. The example uses vendor-neutral servers. Test affinity, state placement, shared backends and startup. |
| PERF-03 | A backlog grows when arrivals exceed completions. Waiting and service both contribute to elapsed time. Variability and saturation can raise tail latency while successful throughput increases. | Google, *Site Reliability Engineering* (2016), [Queue Management](https://sre.google/sre-book/addressing-cascading-failures/#queue-management) and [Monitoring Distributed Systems, Worrying About Your Tail](https://sre.google/sre-book/monitoring-distributed-systems/). Dean and Barroso, CACM 56(2), 2013, [The Tail at Scale, abstract](https://research.google/pubs/the-tail-at-scale/). | Verified. The simplified burst arithmetic supplies neither a measured percentile nor a universal utilization limit. |
| PERF-04 | Representative load testing helps estimate safe capacity. Offered load, successful completion rate, queue depth, latency, errors and resource saturation help isolate a constraint. | Google, *Site Reliability Engineering* (2016), [Demand Forecasting and Capacity Planning](https://sre.google/sre-book/introduction/#demand-forecasting-and-capacity-planning) and [The Four Golden Signals](https://sre.google/sre-book/monitoring-distributed-systems/#xref_monitoring_golden-signals). | Verified as measurement guidance. Profile under matched conditions. Production results require actual experiments. |

Donne Martin's *System Design Primer* at `ae9bbd7b02d90b9866215de185217d33f39ab733` maps [PR-H032 and PR-H034](https://github.com/donnemartin/system-design-primer/blob/ae9bbd7b02d90b9866215de185217d33f39ab733/README.md#L412-L435). Teach scalability across growth axes and distinguish per-operation latency from completions per unit time.
