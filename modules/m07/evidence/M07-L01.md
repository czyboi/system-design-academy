# Source evidence for M07-L01

Checked 2026-11-14. The render job, status contract and application examples are original. The approved inventory and Story SDA-M07-L01 supply topic scope.

| Claim | Exact primary evidence | Applicability |
| --- | --- | --- |
| C1. SQS Standard can redeliver. The visibility timeout hides a received message for a period and a consumer deletes it upon success. A redrive policy can move repeatedly received messages to a DLQ. | AWS SQS Developer Guide [at-least-once delivery](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/standard-queues-at-least-once-delivery.html), [visibility timeout](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-visibility-timeout.html), [DLQ redrive policy](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/sqs-dead-letter-queues.html). | Verified for SQS Standard service documentation on the checked date. Visibility is no exclusive lock. |
| C2. RabbitMQ publisher confirms and consumer acknowledgements cover different hops. Unacknowledged manual-ack deliveries requeue on channel or connection closure. | RabbitMQ 4.2, AMQP 0-9-1 [confirm and acknowledgement scope](https://www.rabbitmq.com/docs/4.2/confirms#are-publisher-confirms-related-to-consumer-delivery-acknowledgements), [automatic requeueing](https://www.rabbitmq.com/docs/4.2/confirms#automatic-requeueing). | Verified for the stated protocol and ack mode. Queue and message settings determine broker-side durability. |
| C3. Redis OSS 6.2+ LMOVE atomically moves a list element to a processing list. Removing completed work and recovering old claims are application responsibilities in this pattern. | Redis [LMOVE, Pattern: reliable queue](https://redis.io/docs/latest/commands/lmove/#pattern-reliable-queue), [persistence modes](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/). | Verified for the documented list pattern. Redis persistence, failure recovery and reaper logic require explicit configuration/design. |
| C4. Celery workers execute registered tasks. Default early ack differs from late ack, with documented process-termination exceptions. | Celery 5.6.0 [Tasks, introduction](https://docs.celeryq.dev/en/v5.6.0/userguide/tasks.html). | Verified for the documented Celery version. Broker transport and worker settings matter. |
| C5. A dual write can leave committed state without its corresponding published message. A transactional outbox persists the handoff intent with the source mutation. | AWS Prescriptive Guidance [Transactional outbox, motivation and considerations](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html). | Verified design pattern. The relay can publish again, so deduplication still matters. |
